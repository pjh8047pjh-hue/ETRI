# Pointwise power comparison

This directory compares only the 64-lane PW2 arithmetic datapath.  It does not
include BRAMs, the scheduler, PS, clock wizard, or board I/O.

- `mac_accum`: 64 registered DSP multipliers, fabric reduction, accumulator
- `cascade`: the existing `pointwise_after_depth.sv`, using 8 groups of 8 DSP
  cascade stages and the existing three DSP Macro IPs

Both variants use the Ultra96-V2 part, a 2.5 ns (400 MHz) clock, OOC
place/route, and identical vectorless port switching activity.  Reports are
written below `results/<variant>/`.

Run from a Vivado 2020.2 command prompt:

```text
vivado -mode batch -source prepare_cascade_ips.tcl
vivado -mode batch -source run_power_compare.tcl -tclargs mac_accum
vivado -mode batch -source run_power_compare.tcl -tclargs cascade
```

The resulting power values are estimates, not board measurements.  For final
sign-off, annotate each routed design with SAIF generated by the same stimulus.

## Routed comparison

| Metric | MAC + accumulator | DSP cascade | Cascade change |
|---|---:|---:|---:|
| Total on-chip power | 0.519 W | 0.481 W | -0.038 W (-7.3%) |
| Dynamic power | 0.297 W | 0.259 W | -0.038 W (-12.8%) |
| Static power | 0.222 W | 0.222 W | no change |
| Logic LUT | 926 | 254 | -672 (-72.6%) |
| Total LUT | 926 | 769 | -157 (-17.0%) |
| LUT used as SRL | 0 | 515 | +515 |
| Registers | 1,841 | 4,228 | +2,387 |
| DSP48E2 | 64 | 64 | no change |
| 400 MHz WNS | -3.122 ns | +0.836 ns | cascade passes |
| 400 MHz TNS | -117.267 ns | 0 ns | cascade passes |

The cascade architecture increases clock power because it contains lane-skew
and pipeline storage, but it removes most of the fabric reduction tree. Its
lower signal, CLB-logic, and DSP power more than offset the clock-power increase.

The MAC result is a comparison core matched to the existing PW2 six-chunk
transaction contract. It follows the arithmetic organization of the old
`pointwise_mac.sv`, but it is not a drop-in replacement for the complete PW2
scheduler. Because this routed MAC design does not meet 400 MHz, its 400 MHz
power number is useful only as an architectural switching comparison; it is not
a feasible 400 MHz operating point.

Power confidence is `Medium` because identical vectorless input activity was
used for both designs. These OOC results exclude BRAM, the controller, PS,
clock wizard, and board I/O. Use the same post-route SAIF stimulus for both
variants before treating the power delta as a sign-off result.

## Open routed results in Vivado GUI

Double-click one of these files. It opens the already-routed checkpoint and
creates Power, Timing, Utilization, and DRC report tabs without rerunning the
implementation or opening the main XPR.

- `open_mac_accum_gui.bat`
- `open_cascade_gui.bat`

In Vivado, select the report tab named `<variant>_power`. If the report tabs are
not visible, use `Window -> Reports` and double-click the named report.
